> 历史设计记录。2026-10-18 起，当前范围与执行约定以 [README](../README.md)、[COLLECTION](../COLLECTION.md) 和三个现有 SKILL.md 为准。下文的数量目标、早期时间表与待拍板事项保留作历史背景，不代表已实现能力。

> 参考对象：[Barrios Skills](https://github.com/Barrios88/barrios-skills)（John Manuel Barrios，耶鲁管理学院会计学副教授，MIT 许可，2026-06 创建、持续更新中）。

> 状态：待阿索拍板的草案，2026-10-15。

## 1. 一句话定位

面向药学本科生的开源 Agent Skill 仓库：把医学统计学的「方法选择纪律、前提条件、结果报告规范」写成 agent 可执行的 Markdown 约定（skills/），配套开放医药数据取数途径与教学数据集，让学生在 agent 辅助下完成「从问题到可复跑的统计分析文件」的全过程。

与 Barrios 的本质差异：他服务**研究者发论文**，我们服务**学生学对统计**。验证闸门因此不同——不是"研究结果是否可信"，而是"方法是否用对、前提是否检验、数字是否来自文件"。

## 2. 从 Barrios 继承什么、改造什么

| 维度 | Barrios 的做法 | 本仓库的处理 |
|---|---|---|
| 两部分分工 | skills/=约定（how），mcp/=实时接入（tools） | 继承。但本科生统计计算（t检验/卡方等）agent 本地即可算，**不需要自研 MCP**；数据源用免 key 的开放 API（openFDA、ClinicalTrials.gov），取数约定写进 skill |
| 组织主线 | empirical loop 九阶段（研究流水线） | 改为**教材方法体系**（按章节组织），另设一个「方法选择路由」skill 承担"按任务选模块" |
| 策展原则 | iron-law checklists 优于 generic tips | 继承并落到医学统计：见第 6 节验证闸门清单 |
| 产物落盘 | data/raw、scripts、tables、DECISIONS.md、LOG.md；对话是"可丢弃的上下文" | 原样继承，目录中文化说明 |
| 验证闸门 | 行数、过滤、审计、基准检查、数字溯源 | 继承，换成教学版核对项（方法特定前提、适用条件、效应量、表格） |
| 生态 | Cursor / Claude / Codex 三端安装说明 | 改为国内学生可及的 agent 环境（扣子/豆包等）+ 通用 SKILL.md 标准格式 |
| 可选集 | skills/optional/（文档、求职工具） | 保留 optional 机制，放 SPSS 对照、考试复习等 |

## 4. Skill 清单（核心 20 个 + optional）

### 4.1 methods-core/ — 统计方法核心（10 个）

| Skill | 内容要点 | 药学例题方向 |
|---|---|---|
| `data-types-and-summary` | 计量/计数/等级资料识别；均数±标准差、中位数（四分位数）、率与构成比 | 血药浓度描述、有效率比较 |
| `statistical-tables-graphs` | 三线表规范；直方图/条图/线图/箱式图/散点图的选择纪律 | 含量测定数据展示 |
| `t-test` | 单样本/配对/两独立样本 t 检验；正态性、方差齐性前提与替代路径 | 两种剂型达峰浓度比较 |
| `anova` | 完全随机、随机区组设计方差分析；多重比较（LSD/SNK/Bonferroni） | 多剂量组药效比较 |
| `chi-square` | 四格表、行×列表、配对计数；n≥40 与理论频数≥5 的适用条件链 | 两组不良反应率比较 |
| `nonparametric` | 符号秩和、成组秩和、多组秩和（Kruskal-Wallis） | 等级资料疗效比较 |
| `correlation-regression` | 直线相关与回归；残差检查；相关≠因果 | 剂量-血药浓度关系 |
| `logistic-regression` | 二分类结局建模；OR 值解读 | 不良反应发生危险因素 |
| `survival-analysis-intro` | Kaplan-Meier 曲线、log-rank 检验（本科选讲） | 起效时间/复发时间比较 |
| `sample-size-design` | 样本量估算（率比较/均数比较）；随机化、对照、盲法 | 临床试验方案作业 |

### 4.2 pharm-applications/ — 药学场景（5 个，本仓库区别于通用统计 skill 集的核心）

| Skill | 内容要点 |
|---|---|
| `bioequivalence` | 生物等效性：双单侧检验、90% CI、80%–125% 界值、log 转换纪律 |
| `pharmacokinetics-stats` | AUC、Cmax、Tmax 的统计处理；个体内/个体间变异 |
| `assay-validation` | 含量测定方法学验证：线性范围、精密度、回收率、耐用性的统计表达 |
| `adverse-event-analysis` | 药品不良事件数据：比例比较、ROR 信号检测入门（接 openFDA FAERS） |
| `clinical-trial-stats` | I–IV 期设计统计学要点；终点指标；ITT/PP 分析集 |

### 4.3 data-and-tools/ — 数据与工具（4 个）

| Skill | 内容要点 |
|---|---|
| `openfda-data` | openFDA API（FAERS、药品标签）取数约定：端点、查询语法、返回字段、限速 |
| `clinicaltrials-data` | ClinicalTrials.gov API v2：试验设计类型、样本量、终点字段提取 |
| `python-stats-recipes` | scipy/statsmodels 执行模板：每个方法 skill 的"软件执行"节统一引用 |
| `teaching-datasets` | datasets/ 的使用说明与变量字典导读 |

### 4.4 reporting/ — 报告与解读（1 个总路由 + 2 个）

| Skill | 内容要点 |
|---|---|
| `method-selection-router` | **总路由**：输入"资料类型 + 设计类型 + 组数 + 前提满足情况"，输出应调用的方法 skill；这就是本科医学统计最核心的能力，做成 agent 可执行的决策树 |
| `stats-report-writing` | 实验报告/统计报告结构；结果段写法；数字必须引自输出文件 |
| `result-interpretation` | P 值、置信区间、效应量、统计意义 vs 专业意义；常见误读清单 |

### 4.5 optional/

- `spss-menu-map`：每个方法的 SPSS 菜单路径与 .sps 语法（课堂对照用；SPSS 无开源接口，只做指引）
- `exam-review`：按章节的自查题与常见错误模式
- 后续可加：毕业论文统计分析专题

**数量控制**：v1 只做核心 20 个左右，不追求 Barrios 的 46 个。每个 skill 都进过课堂验证再上架。

## 5. 单个 skill 的内部结构

沿用标准 SKILL.md 规范（frontmatter + 正文），每个 skill 文件夹：

```
skills/methods-core/t-test/
├── SKILL.md            # 约定主体
├── references/         # 展开材料（前提检验细节、例题）
│   ├── assumptions.md
│   └── examples.md
└── assets/             # 可选：模板、对照表
```

SKILL.md 正文固定六节：

1. **何时用**（写入 frontmatter description，agent 路由依赖它）
2. **何时不能用**（前提与禁忌——教学重点）
3. **执行步骤**（含产出文件要求：结果写入 output/，不进聊天记录）
4. **软件执行**（三轨：SPSS 菜单路径 | R 代码 | Python 代码）
5. **结果报告模板**（统计量、自由度、P、CI、效应量的标准句式）
6. **验证清单**（对应第 6 节闸门中与本方法相关的条目）

## 6. 验证闸门（医学统计版 iron-laws，草案）

写入每个相关 skill 的"验证清单"，并汇总进 README：

1. 先定资料类型（计量/计数/等级）再谈方法——禁止跳过
2. 按候选方法检查相应前提：配对 t 看差值；单样本与配对 t 不要求两组齐性；正态性检验非拒绝不证明正态，也不机械触发秩检验
3. 分类检验先查编码、总数与边际；独立二分类课程条件链、R×C 与 McNemar 各自判断，课程阈值不写成普遍定理
4. 先确认实验/抽样单位与相关结构，不能仅凭数据列名推断设计
5. 按预定方法报告效应、CI 算法与置信水平；无法估计须说明原因
6. P<0.05 ≠ 有专业意义；P≥0.05 ≠ 无差别（检验效能问题）
7. 多重比较必须说明校正方法
8. 报告数字能定位到本次真实输出；SPSS 可准确转录并标注表名及行列，手算过程与软件结果分别标明
9. 统计表一律三线表；统计图注明 n、误差线含义（SD 还是 SEM）
10. 每次分析更新 LOG.md（时间、数据、方法、结论）与 DECISIONS.md（方法选择理由）

## 9. 待阿索拍板的决策点

1. **语言**：建议正文全中文（学生读）、frontmatter 的 name 用英文（目录规范）、description 中文为主。是否同意？
2. **软件三轨**：每个方法 skill 内并列 SPSS 菜单 | R | Python，还是只做 Python + SPSS 对照放 optional？
3. **skill 粒度**：按第 4 节的 20 个核心，还是更粗（如"组间比较"一个 skill 覆盖 t 检验/方差分析/秩和）？我倾向 20 个细粒度——路由更准、单文件更短，但维护量大些。
4. **仓库托管**：GitHub 主仓 + 国内镜像（Gitee）？学生访问 GitHub 不稳定。
5. **与 AFP 教学智能体的关系**：本仓库作为 C3 教学智能体的公开知识内核，还是完全独立项目？（影响 README 写法和后续同步机制）
